\chapter{Cap Set Problem}

\section{The Problem}

\subsection{Informal}

\textbf{Background.} In ordinary arithmetic, when you count 1, 2, 3, 4, the numbers wrap around naturally. But imagine arithmetic on a clock with 3 hours: after 2 comes 0, then 1, then 2 again. This is called modular arithmetic. Now imagine this wrapping happens independently in many directions at once, creating a vast grid of points where each coordinate is 0, 1, or 2.

\textbf{Given.} You are given a grid of points where each point has $n$ coordinates, each coordinate being 0, 1, or 2. There are $3^n$ points in total.

\textbf{Goal.} How large a collection can you build before three evenly-spaced points are unavoidable?

\textbf{Constraints.} The arithmetic wraps around like a clock: $1 + 2 = 0$ and $2 + 2 = 1$. The three points must be distinct. The collection must avoid three-term arithmetic progressions in every direction simultaneously.

\textbf{Example.} In the simplest case $n = 1$, the grid has 3 points: $\{0, 1, 2\}$. The progression $0, 1, 2$ satisfies $0 + 1 + 2 = 3 \equiv 0$, so you cannot pick all three. The largest valid collection has 2 points (for instance, $\{0, 1\}$). As $n$ grows, the question is how large a collection you can build relative to $3^n$.

\subsection{Formal}
\begin{conjecture}[Frankl-Graham-Rödl, 1987]
$r_3(n) = o(3^n)$.
\end{conjecture}

The trivial bound is $3^n$. Meshulam (1995) proved $r_3(n) \le 2 \cdot 3^n / n$, using Fourier analysis. The best pre-2016 bound was $r_3(n) \le 3^n / n^{1+c}$ for a small constant $c > 0$.

\subsection{Historical Context}
The cap set problem is the $\mathbb{F}_3$-analogue of Roth's theorem on arithmetic progressions in the integers (1953). While Roth's theorem was proved using Fourier analysis on $\mathbb{Z}$, the finite-field version resisted analogous techniques for decades.

\subsection{What Was Known}
Roth proved in 1953 that subsets of the integers without three-term arithmetic progressions must be thin. Meshulam extended this to three-dimensional grid arithmetic in 1995, proving that cap sets must be significantly smaller than the full grid. But the best known bound was still far from the conjectured answer. The polynomial method, newly adapted to combinatorics by Croot, Lev, and Pach in 2016, provided the breakthrough.

\subsection{Why It Matters}
The cap set problem is a testing ground for new mathematical techniques. The slice rank method used to solve it has since been applied to many other problems in combinatorics and theoretical computer science. Understanding how large structured sets can be has applications to coding theory and the study of error-correcting codes.

\subsection{Simplified Version}
The classical version of this problem works over the integers: Roth's theorem (1953) says that any subset of the integers $\{1, 2, \ldots, N\}$ without three-term arithmetic progressions must be thin---its size is at most $N / \log \log N$. The cap set problem asks the same question over $\mathbb{F}_3^n$ (the $n$-dimensional vector space over the field with 3 elements), where the arithmetic wraps around like a clock. The polynomial method, adapted from finite-field geometry, finally cracked this harder version.

\section{Mathematical Theory}

\subsection{The Polynomial Method}

The polynomial method is a versatile combinatorial tool with a simple core idea: to show that a set $A$ is small, find a nonzero polynomial that vanishes on all of $A$. If the polynomial has low degree, it cannot have too many zeros, so $A$ must be small.

\begin{definition}[Vanishing Polynomial]
A polynomial $P \in \mathbb{F}_q[x_1, \ldots, x_n]$ \emph{vanishes} on a set $A \subset \mathbb{F}_q^n$ if $P(a) = 0$ for all $a \in A$.
\end{definition}

The key fact connecting polynomials to finite fields is:

\begin{fact}[Schwartz-Zippel]
A nonzero polynomial of degree $d$ over $\mathbb{F}_q^n$ has at most $d \cdot q^{n-1}$ zeros.
\end{fact}

Dvir's 2008 proof of the Kakeya conjecture over finite fields demonstrated the power of this approach: by constructing a low-degree polynomial vanishing on a Kakeya set, he showed such sets must be large. The cap set problem asks whether a similar strategy can beat Meshulam's Fourier-analytic bound.

\subsection{Tensor Rank and Slice Rank}

The breakthrough of Croot, Lev, Pach, and Ellenberg--Gijswijt reformulates the cap set problem in terms of \emph{tensor rank}, a generalization of matrix rank.

A \textbf{matrix} is a 2D array of numbers. Its rank measures how many independent rows (or columns) it has---a rank-1 matrix is just a column times a row. A \textbf{3-tensor} is a 3D array of numbers (think: a cube of entries). Its \emph{tensor rank} measures how many ``rank-1 tensors'' (outer products of three vectors) are needed to build it.

\begin{definition}[Slice Rank]
The \emph{slice rank} of a 3-tensor $T$ is the minimum number of terms needed to express $T$ as a sum of pieces, where each piece is a product of a vector in one factor with a bilinear form on the other two. Concretely, for a 3-tensor $T(x,y,z)$:
\[
T(x,y,z) = \sum_{i=1}^{r} v_i(x) \cdot B_i(y,z) \quad \text{or similar, with one variable factored out per term.}
\]
\end{definition}

\textbf{Concrete example.} Consider the $3 \times 3 \times 3$ tensor $T(x,y,z)$ over $\mathbb{F}_3$ defined by $T(x,y,z) = 1$ if $x + y + z \equiv 0 \pmod{3}$, and $0$ otherwise. This tensor has slice rank 3: you can write it as a sum of 3 terms, each factoring out one variable. But a diagonal tensor $D(x,y,z) = 1$ if $x = y = z$ and $0$ otherwise has slice rank equal to the size of its diagonal support (here, 3). The key fact: \emph{slice rank} $\leq$ \emph{tensor rank}, and for diagonal tensors they are equal. This means slice rank gives a lower bound on how many entries a diagonal tensor must have---and that lower bound is what caps the size of cap sets.

\subsection{The Cap Set Tensor}

For the cap set problem over $\mathbb{F}_3^n$, define the tensor:
\[
T(x,y,z) = \begin{cases} 1 & \text{if } x + y + z = 0 \\ 0 & \text{otherwise} \end{cases}
\]
A subset $A \subset \mathbb{F}_3^n$ is a cap set if and only if $T|_{A \times A \times A}$ is diagonal (i.e., $T(x,y,z) \neq 0$ only when $x = y = z$). The slice rank of $T$ then upper-bounds $|A|$:
\[
|A| \le \text{slice rank}(T).
\]

\begin{highlightbox}
The key insight: the cap set condition is exactly the condition that the restriction of $T$ to $A$ is diagonal. Since diagonal tensors have slice rank equal to the size of the diagonal, any cap set has size at most the slice rank of $T$.
\end{highlightbox}

\subsection{Counting Monomials}

The slice rank of $T$ is bounded by counting low-degree monomials. Consider the vector space $\mathcal{P}_{<2n/3}$ of polynomials in $\mathbb{F}_3[x_1, \ldots, x_n]$ of degree less than $2n/3$ (with each variable exponent in $\{0, 1, 2\}$). Using Stirling's approximation:

\begin{theorem}[Monomial Count]
$|\mathcal{P}_{<2n/3}| \le 2.756^n$.
\end{theorem}

The slice rank of $T$ is at most $3 \cdot |\mathcal{P}_{<2n/3}|$ (the factor 3 accounts for the three tensor factors), giving:
\[
r_3(n) \le 3 \cdot 2.756^n.
\]

\section{The Solution}

\subsection{The Big Idea}

The cap set problem asks: how large can a subset of $\mathbb{F}_3^n$ be if it contains no three equally-spaced points? For decades, the best tools were \emph{two-dimensional}: Fourier analysis decomposes functions into waves (complex exponentials), and these waves can only see correlations between \emph{pairs} of points. But the cap set condition is inherently \emph{three-dimensional}---it involves \emph{triples} $(x, y, z)$ with $x + y + z = 0$. It is like trying to study a three-person relationship using only couple's therapy: the tool is structurally mismatched to the problem.

The breakthrough was to abandon Fourier analysis entirely and switch to \emph{polynomials}. A polynomial of low degree cannot vanish on too many points (Schwartz-Zippel), and the cap set condition forces the existence of such polynomials. Ellenberg and Gijswijt made this precise using \emph{slice rank}---a tensor generalization of matrix rank---which converts the cap set problem into a monomial counting exercise. The answer drops from $3^n$ to $2.756^n$, an exponential improvement.

\subsection{What Was Stopping Progress}

Fourier analysis was the workhorse of additive combinatorics since Roth's 1953 theorem, and Meshulam (1995) used it to prove $r_3(n) \le 2 \cdot 3^n / n$ over $\mathbb{F}_3^n$. But this approach could only peel off polynomial factors from $3^n$---it could not achieve the subexponential bound the conjecture predicted. The reason is structural: Fourier characters are one-dimensional objects, while the cap set condition is a three-body constraint involving triples. Pl\"unnecke-Ruzsa and entropy methods had the same limitation: they are inherently ``lossy,'' discarding higher-order information at each step. Before 2016, the polynomial method had only been used in geometry (Dvir's Kakeya proof) and nobody had applied it to additive combinatorics over $\mathbb{F}_3^n$.

\subsection{The Breakthrough}

Croot, Lev, and Pach (June 2016) used the polynomial method to show progression-free subsets of $\mathbb{Z}_4^n$ are exponentially small. Ellenberg and Gijswijt (July 2016) adapted the idea to $\mathbb{F}_3^n$ using \emph{slice rank}. The key move: encode the cap set condition as a tensor, observe that cap sets force this tensor to be diagonal, and bound the slice rank of the tensor by counting low-degree monomials. Since low-degree polynomials cannot vanish on too many points, the cap set must be small.

\subsection{How It Works}

The key innovation is a three-step reduction:

\textbf{Step 1: From cap sets to diagonal tensors.} Define the tensor $T \in \mathbb{F}_3^n \otimes \mathbb{F}_3^n \otimes \mathbb{F}_3^n$ by
\[
T(x,y,z) = \begin{cases} 1 & \text{if } x + y + z = 0 \\ 0 & \text{otherwise} \end{cases}
\]
A subset $A$ is a cap set if and only if $T|_{A \times A \times A}$ is \emph{diagonal} (i.e., $T(x,y,z) \neq 0$ implies $x = y = z$). For diagonal tensors, the slice rank equals $|A|$, so
\[
|A| \le \text{slice rank}(T).
\]

\textbf{Step 2: Bounding slice rank by polynomial counting.} The slice rank of $T$ is bounded by $3 \cdot |\mathcal{P}_{<2n/3}|$, where $\mathcal{P}_{<2n/3}$ is the space of polynomials in $\mathbb{F}_3[x_1, \ldots, x_n]$ of degree less than $2n/3$ (with each variable exponent in $\{0,1,2\}$).

\textbf{Step 3: Stirling's approximation.} The number of such monomials is $\sum_{k < 2n/3} \binom{n}{k} 2^k$, which by Stirling's approximation is at most $2.756^n$. Therefore
\[
r_3(n) \le 3 \cdot 2.756^n.
\]

The constant $2.756$ comes from optimizing the entropy bound: it is the exponential rate of $\max_{0 \le t \le 2} 3^{H(t/3)}$ where $H$ is the binary entropy function, evaluated at the critical point.

\begin{theorem}[Ellenberg-Gijswijt \cite{ellenberggijswijt2017}]
$r_3(n) \le 2.756^n$ for sufficiently large $n$.
\end{theorem}

\begin{highlightbox}
\textbf{The punchline:} The slice rank method is a powerful generalization of the polynomial method: instead of a single polynomial vanishing on a set, one uses the rank of a tensor. This upgraded tool can handle three-body constraints (like the cap set condition) that defeat two-body tools like Fourier analysis. It has since been applied to many problems including the sunflower lemma, the Erd\H{o}s-Ginzburg-Ziv theorem, and the problem of finding large subsets of $\mathbb{F}_p^n$ with no solutions to linear equations.
\end{highlightbox}

\subsection{After the Proof}

The cap set problem is settled in the sense that an exponential upper bound $r_3(n) \le 2.756^n$ has been proved, replacing all previous bounds. However, the full conjecture---that cap sets should be subexponential ($2^{o(n)}$)---remains open. The gap between $2.756^n$ and the conjectured answer is still exponential, and removing the exponential dependence is a major open question. It is possible that the true growth rate is polynomial or even sub-polynomial, but no known technique can achieve this.

The slice rank method that cracked the cap set problem has been applied far beyond its original setting. It has been used to prove results about sunflowers, the Erd\H{o}s--Ginzburg--Ziv theorem, and other problems in additive combinatorics and theoretical computer science. The polynomial method, upgraded through slice rank, has become a standard tool alongside Fourier analysis and the probabilistic method in extremal combinatorics. It has connections to tensor complexity theory and the study of communication complexity.

The central open question is whether the exponential bound can be improved to subexponential. The Ruzsa--Szemer\'{e}di conjecture (also known as the cap set conjecture in its original formulation) predicts that cap sets should be subexponential, and proving or disproving this remains one of the most important problems in additive combinatorics. Understanding the limitations of the polynomial method---why it gives $2.756^n$ rather than something smaller---is itself a deep question. New techniques beyond slice rank may be needed to break the exponential barrier.

\section{Impact}
\begin{itemize}
\item \textbf{Polynomial method 2.0}: Slice rank opened a new chapter in the polynomial method, extending it from geometry (Dvir's Kakeya) to combinatorics.
\item \textbf{Roth's theorem over $\mathbb{F}_3$}: The bound $2.756^n$ is exponentially better than previous methods.
\item \textbf{Connections to TCS}: The slice rank is related to the non-deterministic communication complexity of tensor operations.
\end{itemize}

\section{Computational Verification}

The cap set problem can be explored computationally by exhaustively searching for the largest cap sets in $\mathbb{F}_3^n$ for small $n$.

\subsection{Exhaustive Cap Set Search}

\begin{verbatim}
from itertools import product

def is_cap_set(S, n):
    """Check if S is a cap set in F_3^n (no three-term AP)."""
    S_set = set(tuple(x) for x in S)
    for x in S:
        for y in S:
            # z = 2*y - x (mod 3)
            z = tuple((2 * y[i] - x[i]) % 3 for i in range(n))
            if z in S_set and z != x and z != y and x != y:
                return False
    return True

def f3_vectors(n):
    """Generate all vectors in F_3^n."""
    return list(product(range(3), repeat=n))

def max_cap_set_size(n):
    """Find the maximum cap set size in F_3^n via greedy search."""
    vectors = f3_vectors(n)
    best = []
    # Greedy: add vectors one by one if they don't create a 3-AP
    for v in vectors:
        candidate = best + [v]
        if is_cap_set(candidate, n):
            best = candidate
    return len(best), best

for n in range(1, 5):
    size, cap = max_cap_set_size(n)
    bound = 3**n
    print(f"F_3^{n}: max cap set size = {size} / {bound} = {size/bound:.4f}")
\end{verbatim}

\subsection{Verifying the Ellenberg--Gijswijt Bound}

Compare the computational maximum with the theoretical bound $2.756^n$.

\begin{verbatim}
import math

for n in range(1, 8):
    ej_bound = 3 * 2.756**n
    total = 3**n
    print(f"n={n}: total={total}, EG bound={ej_bound:.1f}, "
          f"ratio={ej_bound/total:.4f}")

# Monomial counting: number of monomials of degree < 2n/3
def count_monomials(n):
    """Count monomials in F_3[x_1,...,x_n] with degree < 2n/3."""
    count = 0
    for deg in range(2 * n // 3):
        # Number of monomials of exact degree deg in n variables over F_3
        # Each variable has exponent 0, 1, or 2
        count += sum(1 for comps in product(range(3), repeat=n)
                     if sum(comps) == deg)
    return count

for n in [3, 6, 9, 12]:
    mc = count_monomials(n)
    print(f"n={n}: monomials deg<2n/3 = {mc}, ratio to 3^n = {mc/3**n:.4f}")
\end{verbatim}

\begin{highlightbox}
Students should run these scripts to observe: (1)~the greedy algorithm finds cap sets whose sizes approach but don't reach the theoretical bound, (2)~the ratio $|A|/3^n$ decreases as $n$ grows, confirming the subexponential conjecture, and (3)~the monomial counting exercise makes the slice rank argument concrete.
\end{highlightbox}
